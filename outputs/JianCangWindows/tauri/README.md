# 见藏 Windows WebView2

0.36.48 使用 Tauri 2 和系统 WebView2。构建时从上级目录生成共用界面。图库读写、文件校验和离线处理复用现有 Node.js 模块，素材服务通过每次运行重新认证的本地回环连接传输数据。

支持本地库、Eagle 和见藏同步库。首次添加 Eagle 或见藏同步库时为只读，可在素材库管理中启用写入。Eagle 写入使用其本机 API，见藏同步库的写入需要格式 6。

- 启动时先读取上次的素材库，确认没有已添加的库后才显示「打开素材库」。读取失败时可重试。
- 图库左右方向键按排序顺序选择素材，等高布局可跨行。等高布局上下方向键选择相邻行中位置最接近的素材，瀑布流上下方向键沿当前列移动。
- 图库排序减少多余的比较。同步库并行读取变更记录，再按顺序校验和应用。
- 单选和多选右键菜单共用样式。批量评分、复制和导出等操作可在多选右键菜单中使用。
- 图库和大图预览支持 1–5 评分、0 清除评分。「帮助与快捷键」可开启在评分保存后自动选择下一张，默认关闭。
- 在素材右键菜单中可将单项或多项加入暂存选片。左侧「暂存选片」汇集不同集合和素材库的条目，重启后保留。对照支持选中 2–4 张图片联动缩放和拖动，两图仍支持滑动对照。
- 本地素材库保留回收站条目 30 天。连接素材库、启动应用和应用运行期间会检查到期条目。旧条目缺少移入时间时，从新版首次检查时开始计时。
- 移到回收站的确认窗支持长文件名换行。确认后图库立即更新，写入在后台完成。写入失败会恢复素材并显示原因。
- 关闭主窗口可退出见藏或最小化到系统托盘，支持记住选择。「见藏 → 窗口与启动设置」可更改关闭方式。正式安装版可在同一处设置 Windows 登录时启动，默认关闭。
- 支持从资源管理器拖入、粘贴剪贴板、监视文件夹和跨库复制。支持网页图像一次拖入 32 张，原始图片数据每批最多 32 MiB。拖出时使用系统临时缓存和 Windows 缩略图拖影。显式复制文件时会在「下载 / 见藏拖出」准备可粘贴的副本。
- 一次拖入多个视频时优先使用本机原件路径。其他应用提供可读取的视频文件时，见藏分块读取文件并暂存到导入队列。
- 拖入后可在目标库或集合查看待导入卡片和进度，原件写入完成后显示为正式素材。同步库批量导入合并目录刷新，持续导入期间也会定期更新。
- 「导入队列」可一次取消当前目标库的全部等待任务。暂停期间也可取消。
- 重复整理支持精确与相似扫描、本地重复项的标签和集合合并。支持离线 OCR、AI 整理建议和自然语言找图。
- AI 整理可收起到后台。底部状态栏显示进度并可重新打开。暂停后或重启见藏后，点击继续会从未完成项接续。「重试失败项」一次处理当前批次中的失败项。
- AI 整理可以分次应用同一素材的不同字段。还有未处理或失败的建议时，应用后保留窗口。「勾选空白项」会为陆续生成的结果补选空白字段和自动生成的文件名。
- 支持批量原件导出、导出预设、图片转格式、裁剪与旋转、灵感板工程与 PNG/PDF 导出、多段视频裁剪和当前帧导出、视频备注 CSV/SRT 以及本地库备份和恢复。
- 同一份格式 6 见藏同步库可在 Windows 与 iPhone、iPad 间接续视频时间点备注、灵感板和高级智能集合。Windows 开启库写入后可保存共享修改。原有视频备注可用「同步本机备注」接续，符合跨端条件的本机灵感板和智能集合可复制到同步库。
- 本地库可在「管理素材库 → 备份与恢复」设定每日增量备份。只保存变动内容，恢复时按日期选快照并创建独立素材库。运行期间执行计划，关闭时错过的计划在下次打开后补做。
- 可取回云端原件，暂停、重试或查看失败记录。存储管理可查看和清理生成的缩略图缓存。
- 图片可在置顶参考窗中拖动、缩放和复制。ICO 可在图库、详情、大图和参考窗预览。链接素材支持保存公共网页正文供离线阅读。本地库回收站可以在确认后永久删除或清空。
- Edge 或 Chrome 采集支持自动归档和采集历史。安装后可用签名发布通道或本地更新文件夹检查、校验和安装更新。

正式安装方式使用当前用户的 `Programs\JianCang-WebView2` 和「见藏」快捷方式。同一位置已有其他应用的同名快捷方式时，新版使用「见藏（新版）」。首次启动接续旧 Electron 版的库连接、采集设置和兼容的历史记录，优先保留此前在 Tauri 中的设置。旧版批量改名、原件导出和图片导出预设可用「帮助 → 导入旧版预设」接续，同名预设保留新版设置。AI API 密钥需要重新输入，主题在新版重新设置。旧版的待处理任务可在 Electron 中完成，本地灵感板可用「导出工程」和「导入工程」转移。

做写入测试时使用试验库或素材库副本。安装时会请求已安装的旧版正常退出。切回旧版前先退出 WebView2 版。

## 构建

Windows x64 需要 Rust MSVC 工具链、Visual Studio C++ Build Tools、Node.js、Python 3 和 Git。将 `-NodeArchive` 指向 Node.js 官方的 `node-v24.22.3-win-x64.zip`。准备脚本校验 Node 和离线 OCR 文件，并通过现有 Windows 打包脚本准备固定版本的 FFmpeg 及对应源码。首次构建需要获取 FFmpeg 的运行时、源码和构建配置，缓存位于 `work/build/jiancang-ffmpeg`。

```powershell
.\Build-Windows.ps1 -NodeArchive C:\Downloads\node-v24.22.3-win-x64.zip
```

提供 `-MakeNsis` 可同时生成安装程序，加 `-Production` 使用正式安装方式。便携版解压后运行 `jiancang-tauri.exe`，保留同级 `backend` 文件夹。安装程序使用系统 WebView2，完成页提供默认勾选的启动选项。

在 Windows 项目目录使用 Node.js 24 运行 `node --test tauri/backend/*.test.cjs` 可验证素材服务。测试使用临时的合成库。

为正式安装包生成更新清单时，从工作区执行 `node work/build/jiancang-sign-tauri-update.cjs --production <安装包> <项目 Ed25519 密钥文件>`。将安装包和 `jiancang-windows-webview2-x64-update.json` 一起放在更新目录。GitHub 的 WebView2 通道使用 `tauri-windows-x64` 标签。在「更新设置」中恢复官方通道即可选择它，在线切换前需在 Windows 上验收系统代理和安装器交接。
